# Cloud delivery contract

- collect.py and sources.json configure 50 public sources, including a paginated Duma archive, two short Government RSS tails, and a bounded official-publication API title search. Duma stops at the requested date boundary or 16 pages / 120 seconds. Publication API uses DD.MM.YYYY publication-date bounds, five full-phrase Name queries, at most two pages of 200 per query / 120 seconds. Caps are visible via window_coverage/pages_fetched; metadata matching is not full legal-text monitoring.
- Every run restores a persistent archive from state/items.jsonl into data/archive.sqlite3, collects, then exports state/items.jsonl. This is sorted JSONL with the same public item keys as data/latest.json items (canonical_url, url, title, excerpt empty, published_utc, first_seen_utc, topics, regions, source_ids, provenance, source_kind). No secret or client context is exported.
- data/latest.json: generated_at, publication_window_days, recent_unique_items, buckets {privacy_world, privacy_ru, ai_world, ai_ru}, source_health, undated. Buckets share canonical_url. Source metadata is in each item's provenance; topic-region membership is derived from observation topics + source region.
- publish_site.py reads data/latest.json and writes only static public titles/links/date/source/status into site/. No long excerpts, no personal email, no local paths. Self-contained CSS/JS, four filters, search, responsive.
- notify.py reads data/latest.json, persists state/notifications.json. GitHub issue delivery is the same mechanism as ilyak0/pos-job-watch: bot creates issue mentioning @ilyak0. Default local command prepares only; --publish explicitly creates issue using GH_TOKEN/GITHUB_REPOSITORY. Site URL from PAGES_URL env default https://ilyak0.github.io/privacy-ai-watch/. Title Privacy & AI — YYYY-MM-DD (Europe/Moscow date). Hidden daily marker and per-item SHA256 markers provide idempotency/recovery.
- At most one notification issue per Moscow calendar day. Existing daily issue must be checked before creation; on rerun recover notified markers and do not post another. Newly seen later items wait for next day. Only previously unnotified keys in the recent window go to digest; first digest uses last7d, with older initial archive baselined in ledger. Do not mark unshown cap overflow as notified. Preserve old ledger keys. All publications remain available in Pages window.
- Source error/stale/empty counts visible; old archived articles are not described as fetched this run. A day without new items and without errors produces no issue; no repeated stale-source spam. A day with genuine errors may have one bounded alert issue.
- Workflow: public dedicated repo, collection six-hourly + daily email08:37MSK (05:37UTC), Pages artifact deployment. Core feeds need only built-in GITHUB_TOKEN; the optional enabled X reader also has the separately approved encrypted session secret. Existing private vacancy repo stays untouched.
- editorial.py gives deterministic practice / AI context / events groups, with laws, decisions, guidance and direct sources prioritized within practice. Mail and Pages preserve all selected items and exact source kinds; classification does not assert jurisdiction, validity or entry into force.
- post_ideas.py selects at most three questions per LinkedIn/Telegram/X from explicit headline themes in the last seven days, one candidate per theme. Direct sources are preferred. Each idea retains title, URL, publication date, source kinds and basis=headline. Mail uses newly selected digest items; Pages uses its recent archive. No social posting, LLM/API credentials or private inputs.
- Source x-curated is enabled after explicit session-owner consent. Transport x_cookies reads only allowlisted public account timelines through x_reader.py; never a personal/home timeline, search, messages or write operations. Cookies are supplied at runtime from X_READER_COOKIES_JSON or a local X_READER_COOKIES_FILE, never persisted in public state. Twikit is isolated in requirements-x.txt and installed in Actions only when X_READER_ENABLED is true. The encrypted session secret and activation variable are configured separately from public source metadata; no session values are committed or exported.

- briefing.py selects up to five practice headlines within seven days, preferring direct primary sources and limiting two per publisher family/theme. It collapses same-actor/topic story rewrites (including minor fine rounding), keeps distinct cases, and preserves evidence plus headline basis. Reasons to open and verification notes are editorial prompts, not legal conclusions. Mail uses only unnotified selected items; Pages uses the current recent archive. Full news and notification markers are retained.

- `stories.json` defines stable, specific headline rules. `timelines.py` updates `state/timelines.json` from the permanent article archive after export, atomically and without an age purge. Initial history is baselined per story; future matching publications receive stable canonical-URL hashes. The public timeline exposes dates of publications and separate source links/kinds, never inferred legal status or private BK analysis. Stories with one publication are explicitly marked as watching.
- `notify.py --timelines` joins pending timeline entries to normal news by canonical URL and uses the same item/body caps. A story row replaces its bulk-list row. Confirmed issues carry both item and timeline markers, with delivery recorded in `timeline_events`; recovery restores both. Unshown capped entries stay pending. The CLI loads production timeline state; pure test APIs require an explicit input path/state.
- `publish_site.py --timelines` reads persistent history separately from the rolling report and includes `timelines` in public news.json. Story links use `#story-<stable-id>`, open the relevant history and retain entries older than 30 days. See TIMELINE_SCHEMA.md for the data contract.

- `noyb-discovery` is an additional Google News backup with kind=discovery, alongside the unchanged official noyb RSS. It does not conceal the official feed failure or assert original availability. Its configured title_suffix_pattern strips only the terminal publisher suffix before the existing exact-headline/publication-day alias merge; source observations and their kinds remain separate.
- Alias merges retain the first-seen canonical URL and main link to preserve timeline and delivery identities. If discovery arrives first, its link stays canonical; a later direct source retains its own URL and kind in provenance. Neither order promotes discovery to primary.
