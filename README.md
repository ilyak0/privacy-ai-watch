# Privacy & AI Watch

Новости о privacy и AI: международные и российские / русскоязычные источники.

**[Открыть архив](https://ilyak0.github.io/privacy-ai-watch/)** ·
**[Ежедневные дайджесты](https://github.com/ilyak0/privacy-ai-watch/issues)**

## Доставка

GitHub Actions собирает публичные источники каждые шесть часов и публикует
обновлённый архив на GitHub Pages. Отдельный утренний запуск запланирован
на **08:37 по Москве**; GitHub может задерживать запуск расписания.
Mac и BB для работы не нужны.

Утренний дайджест создаётся как GitHub issue с упоминанием `@ilyak0`.
GitHub доставляет уведомление на почту по настройкам аккаунта — тот же
механизм, что используется для вакансий в pos-job-watch. Публикации выдаются
однократно, журнал доставки сохраняется. Повторный запуск в тот же день
не создаёт второе письмо. Первый дайджест охватывает последние семь дней;
более ранние публикации доступны в архиве.

В начале письма — «Сначала открыть»: до пяти поводов за неделю с пояснением,
зачем читать публикацию, и меткой типа источника. Первоисточники имеют
приоритет; перепечатки одного события объединяются, одна тема или источник
не занимают больше двух мест. Затем — вопросы для постов. Полный перечень
новых публикаций раскрывается отдельно: практика, контекст ИИ и мероприятия. На карточках остаются четыре
метки потоков: privacy / мир, privacy / РФ, AI / мир, AI / РФ.
Если выпуск превышает допустимый размер,
остаток сохраняется для следующего выпуска и доступен в архиве.

Отдельный блок — до трёх вопросов для каждой площадки: LinkedIn, Telegram и X / Twitter:
практический ракурс, точный заголовок, дата и ссылка на новостной повод.
Выбор идёт по явным темам заголовков за последние семь дней; первоисточники
имеют приоритет, одна тема не повторяется внутри канала. В письме используются
только новые материалы этого выпуска; в архиве — всё свежее окно. Это
заготовки вопросов по заголовкам, перед постом нужно прочитать полный источник.
Автоматической публикации в соцсетях нет. Отбор и редакционные разделы
работают по проверяемым правилам без вызовов LLM.

## История сюжетов

На странице есть постоянные таймлайны семи выбранных сюжетов: Xandr, спор
Thomson Reuters/ROSS, музыкальные данные Nvidia, Grok и дипфейки, Google и
данные о местоположении, центр судебных компетенций ВС РФ, внедрение EU AI Act.
Каталог и правила совпадения по заголовку находятся в `stories.json`.
Имена участников и конкретный вопрос должны совпадать вместе; общий регион
или русский язык публикации не определяют принадлежность к сюжету.

`state/timelines.json` хранит накопленные публикации независимо от окна
последних 30 дней. Начальные 15 записей взяты из публичного архива, включая
запись 2024 года. По сюжетам с одной записью прямо показано, что история
ещё формируется. Это хронология доступных публикаций: её даты не заменяют
даты самих юридических событий, а полнота истории дела не утверждается.
Разные публикации не объединяются в одно событие по догадке; тип каждого
источника виден отдельно. Старые внутренние заметки и авторские выводы BK
не копируются и не публикуются.

В утреннем письме блок «Новое по сюжетам» показывает новые записи и ссылку
на накопленную историю. При включении существующие записи становятся
историей и не рассылаются заново. URL и запись сюжета имеют отдельные маркеры
доставки: повторный запуск восстанавливает их из сегодняшнего issue;
не вошедшие в размер письма остаются для следующего выпуска.

## Источники и границы покрытия

Реестр — `sources.json`: 50 включённых источников, из них 29 международных и 21
российских / русскоязычных. RSS/Atom, новостные страницы ведомств,
публичные страницы Telegram, поисковый индекс Google News.

Напрямую подключены архив новостей Госдумы с переходом по страницам
до границы 30-дневного окна (максимум 16 страниц / 120 секунд), RSS
Правительства (документы и общий поток — по 20 последних записей)
и поиск метаданных портала официального опубликования за 30 дней.
Последний ищет по пяти тематическим фразам, до двух страниц по 200 результатов
на запрос / 120 секунд; кандидаты затем проходят локальный тематический отбор.
Достижение лимита видно в состоянии источника. Это отбор заголовков
и метаданных, он не заменяет полнотекстовый реестр актов. Прямое подключение
новостей РКН, Минцифры и судов пока не подтверждено; поисковые потоки для
них сохраняются с меткой `discovery`.

Для noyb дополнительно включён резервный поток Google News. Он собирается
параллельно официальной RSS и помечен `discovery`: результат индекса ещё
не подтверждает доступность оригинала. Из его заголовка убирается только
суффикс издателя, чтобы точное совпадение заголовка и дня могло объединиться
с уже известной статьёй; обе ссылки и типы источников сохраняются.

- `primary` — прямая публикация указанного ведомства.
- `commentary` — авторская публикация, СМИ или отраслевой материал.
- `discovery` — результат поискового индекса; оригинал отдельно не проверен.

Регион обозначает поток источника. Русскоязычный канал может обсуждать
международное событие. Полный охват всех стран и документов не гарантируется:
поисковая индексация неполна, а публичный Telegram показывает хвост истории.
Пустая или старая лента не означает отсутствия изменений законодательства.

На Pages публикуются только заголовки, ссылки, даты, метки и состояние
источников. Длинные выдержки не публикуются. Юридические выводы не генерируются:
законы и решения для анализа нужно отдельно читать по первоисточнику.
Основному сборщику не нужны клиентские документы, почта, пользовательская
сессия Telegram или дополнительные секреты. Для issue используется
встроенный `GITHUB_TOKEN`.

### X / Twitter как источник

Включён источник `x-curated`: публичные аккаунты
из прежнего мониторинга, с отбором по privacy и AI. Он использует Twikit и
сессию cookies вместо платного X API. Cookies не входят в репозиторий, архив
или Pages. Для автономного запуска на GitHub нужен отдельный зашифрованный
секрет `X_READER_COOKIES_JSON`. Владелец сессии согласовал его установку;
сборщик читает только отобранные публичные профили. При истечении сессии
источник показывает ошибку; остальные потоки продолжают работать.

## Данные и повторный запуск

`state/items.jsonl` — постоянный архив публичных метаданных;
`state/notifications.json` — журнал доставки. Сбор на runner восстанавливает
SQLite из JSONL и сохраняет обновлённое состояние обратно. Дата публикации
и дата первого обнаружения различаются; отсутствие даты не заменяется
сегодняшней. Сбой одного источника не очищает архив остальных.

```sh
python3 -m pip install -r requirements.txt
python3 -m unittest discover -v
python3 cloud_state.py restore
python3 collect.py --days 30
python3 cloud_state.py export
python3 timelines.py
python3 publish_site.py
python3 notify.py             # Только подготовка, без отправки.
```

Ручной облачный запуск: Actions → Privacy and AI news → Run workflow.
Включение `notify` создаёт сегодняшний дайджест, если он ещё не создан.
